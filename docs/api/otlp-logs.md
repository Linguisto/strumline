# OTLP/HTTP logs

Telemetria accepts `ExportLogsServiceRequest` at `POST /v1/logs` on the existing
**ingest port (8001)**. Both `application/x-protobuf` and `application/json`
encodings are supported, with optional `Content-Encoding: gzip`. Responses use
the request's encoding. gRPC, traces, metrics, and profiles are not implemented.
This is the sole ingestion endpoint for both single records and batches. The
former `/v1/ingest` and `/v1/ingest/batch` routes have been removed and return `404`.
Their custom JSON bodies must be converted to OTLP; there is no compatibility alias.

## Authentication and routing

Send the existing app token in `x-telemetria-token`. The token alone determines
project/app routing. Resource attributes such as `service.name` are preserved
as data and never change ownership. The resolver uses the ingest database role.
Missing/invalid/revoked tokens return `401`; a database outage on a cache miss
returns retryable `503`. Revocation takes effect within the 60-second cache TTL.

## SDK configuration

Configure an OpenTelemetry logs SDK/exporter with:

```bash
export OTEL_EXPORTER_OTLP_LOGS_ENDPOINT=http://localhost:8001/v1/logs
export OTEL_EXPORTER_OTLP_LOGS_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_LOGS_HEADERS="x-telemetria-token=${TELEMETRIA_TOKEN}"
export OTEL_EXPORTER_OTLP_LOGS_COMPRESSION=gzip
export OTEL_BLRP_MAX_EXPORT_BATCH_SIZE=128
```

Set `TELEMETRIA_TOKEN` to a token created for the destination app first. These
variables configure an installed exporter; the application still needs a logs
SDK/logging bridge. Configure only the logs exporter for this endpoint.
Language SDK support for environment configuration varies; equivalent explicit
exporter options work as well. The batch size above stays under Telemetria's
300-record default, but large bodies/attributes can still exceed byte limits.

## Collector configuration

A Collector can receive either OTLP transport and export logs to Telemetria.
This example receives HTTP locally and uses binary Protobuf with gzip upstream:

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 127.0.0.1:4318
processors:
  batch:
    send_batch_size: 128
    send_batch_max_size: 128
exporters:
  otlphttp/telemetria:
    logs_endpoint: http://localhost:8001/v1/logs
    headers:
      x-telemetria-token: ${env:TELEMETRIA_TOKEN}
    compression: gzip
service:
  pipelines:
    logs:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/telemetria]
```

Use the ingest container's hostname when running the Collector on the same
Docker network. `localhost` above assumes both processes run on the host.
Use `encoding: json` on the exporter to select OTLP JSON instead.

## Mapping and preservation

Each log record becomes one canonical event. Its payload contains `otlp` with
`resource`, `resourceSchemaUrl`, `scope`, `scopeSchemaUrl`, and `logRecord`.
These objects use typed OTLP JSON: AnyValue wrappers remain intact, 64-bit
integers use decimal strings, bytes use base64, and trace/span IDs use hex.
Known fields, including dropped-attribute counts, flags, event name, and both
nanosecond timestamps, survive IPC and Loki serialization. Unknown protocol
fields are ignored, as required for forward-compatible receivers. Protobuf
default-valued fields can be omitted from the stored JSON.

- `message`: string body verbatim; other bodies render as compact typed JSON.
- `level`: severity-number range mapped to trace/debug/info/warn/error/fatal;
  absent or unknown numbers map to `unspecified`. Original number/text remain
  in `payload.otlp.logRecord`.
- `timestamp`: event time, then observed time, then server receipt time.
  This UTC projection has microsecond precision; exact nanoseconds remain in
  the payload. Epoch nanoseconds always denote UTC.
- `received_at`: always generated by Telemetria, never copied from observed time.
- Loki ordering continues to use `received_at`. Resource attributes and
  trace/span IDs remain JSON data rather than high-cardinality Loki labels.

An accepted trace/span identifier is preserved verbatim (canonical lowercase
hex); its presence does not establish valid trace context. Consumers should
ignore IDs with invalid length or all-zero content, per the OTLP log model.

## Limits and delivery

`MAX_PAYLOAD_BYTES` (default 1 MiB) bounds the raw body, decompressed body, and
sum of normalized IPC event bodies per request. Normalization repeats shared
resource/scope information and can expand binary data, so a wire payload below
the limit can still produce partial rejection. Each event must also fit the
1 MiB IPC frame limit. Records are considered in request order; records that
exceed either normalized limit are rejected while later fitting records may
still be accepted. OTLP JSON nesting is limited to 64 message levels; binary
Protobuf also has its runtime decoder's recursion limit.

`MAX_BATCH_EVENTS` (default 300) counts all records across all resources/scopes.
Choose exporter/Collector batch sizes accordingly. Batches larger than the
configured queue capacity can never fit and are rejected permanently.

| Status | Meaning |
|---|---|
| `200`, empty export response | All records admitted; an empty request also succeeds |
| `200`, `partialSuccess` | Normalized size rejections, with exact `rejectedLogRecords` count; do not retry |
| `400` | Invalid payload/gzip, too many records, or batch larger than queue capacity; nothing admitted |
| `401` | Missing or invalid token |
| `413` | Raw or decompressed body exceeds the byte limit |
| `415` | Unsupported content type or content encoding |
| `503` | Temporary authentication outage or insufficient queue space; nothing admitted, retry with backoff |

Failures use `google.rpc.Status`, encoded as JSON or Protobuf. Parser errors
never echo input data. Queue admission is atomic within the ingest event loop;
a retryable capacity failure never partially enqueues a batch. Normalized size
rejections increment `telemetria_ingest_events_dropped_total` with reason
`otlp_normalized_size`.

Success acknowledges admission to an in-memory queue, **not durable delivery**.
Subsequent IPC failures, process restarts, or sink failures can lose accepted
records. Network ambiguity and retries can duplicate records. See
[the sink failure model](../sinks.md).

## Verification

`make test.unit` includes wire-format, gzip, limits, backpressure, mapping,
IPC/Loki preservation, and a real Python SDK HTTP-exporter test.
For additional Collector interoperability (tested with Collector 0.161.0),
install the official `otelcol` binary and run:

```bash
OTELCOL_BINARY=/absolute/path/to/otelcol make test.integration DC_EXEC="uv run"
```

The Collector tests use ephemeral loopback listeners and verify both Protobuf
and JSON export with gzip. They skip when `OTELCOL_BINARY` is unset. The other
integration tests require the normal test PostgreSQL configuration.

References: [OTLP transport specification](https://opentelemetry.io/docs/specs/otlp/)
and [OpenTelemetry log model](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
