# CI, workflows, and release

## Workflows

Three GitHub Actions workflows in `.github/workflows/`:

### `lint.yml` — Lint & Test (feature branches + PRs)

Triggers: push to any branch except `main`, plus all pull requests.

Steps: checkout → install uv → install Python 3.14 → `uv sync --locked --dev` → ruff lint → ruff format check → mypy → import-linter → pytest unit tests only (`-m unit`).

This is the fast feedback loop. Integration tests do not run here (no PostgreSQL).

### `ci.yml` — CI (main branch)

Triggers: push to `main` only.

Four sequential jobs:

1. **Lint** — same checks as `lint.yml`
2. **Build** — `make build.dev`, exports `telemetria:dev` as a gzipped tar artifact (retained 1 day)
3. **Test** — loads the artifact, starts PostgreSQL via `docker compose up -d postgres`, waits for `pg_isready`, runs `make test` (full suite including integration)
4. **Push** — loads artifact, logs in to GHCR, tags as `ghcr.io/<owner>/<repo>:dev`, pushes

The dev image is always pushed to GHCR after a green main build.

### `release.yml` — Release (version tags)

Triggers: push of tags matching `v*.*.*`.

Three jobs:

1. **Changelog** — `git-cliff` with `cliff.toml` to generate release notes from commits
2. **Publish** — builds the `runtime` Docker stage, pushes to GHCR with semver tags (`x.y.z`, `x.y`, `sha-<short>`, `latest`)
3. **Release** — creates a GitHub release with the generated changelog body

## Release flow

1. Merge to `main` → CI runs, dev image pushed to GHCR
2. Tag `vX.Y.Z` → release workflow fires, production image published, GitHub release created

Changelog is generated by `git-cliff` (config in `cliff.toml`). Commit messages feed directly into release notes — write them accordingly.

## Local workflow

```bash
make lint           # ruff + mypy + import-linter (inside container by default)
make test           # full pytest suite
make test.unit      # unit only (no DB)
make test.integration  # integration only

# Override to run locally instead of in container:
make lint DC_EXEC="uv run"
make test DC_EXEC="uv run"
```

`DC_EXEC` defaults to `docker compose run --rm telemetria-cli`.

## Quality gates (all must pass before merging)

- `ruff check telemetria/ tests/` — zero errors
- `ruff format --check telemetria/ tests/` — zero diff
- `mypy telemetria/` — zero errors (strict mode)
- `lint-imports` — all boundary contracts pass
- `pytest` — all tests pass (unit + integration on CI/main, unit-only on PRs)

## Image tagging convention

| Context | Tag |
|---|---|
| Dev build (main branch) | `:dev` |
| Release (tag `vX.Y.Z`) | `:X.Y.Z`, `:X.Y`, `:sha-<short>`, `:latest` |

Registry: `ghcr.io/<owner>/<repo>` (lowercased). `TELEMETRIA_IMAGE_TAG` env var controls which tag compose uses locally.

## Adding a new CI check

1. Add to both `lint.yml` (PR fast path) and `ci.yml` lint job so it runs everywhere.
2. If it requires the Docker image or a database, add it to the `test` job in `ci.yml` only.
3. Update the quality gates list above.
